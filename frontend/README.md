# Frontend (React + Vite)

Self-contained SPA: this directory is the Docker build context and the npm project.
Day-to-day commands go through the root `Makefile` (`make fe-*`); everything below also
works standalone.

```bash
npm ci
npm run dev          # Vite on :5173, backend paths proxied to http://localhost:8050 (VITE_PROXY_TARGET)
npm run lint && npm run typecheck && npm test && npm run build
docker build -t frontend . && docker run --rm -p 8080:8080 -e APP_ENVIRONMENT=stage frontend
```

## Stack

React 19 · Vite 8 · TypeScript 5.9 (strict) · [openapi-fetch](https://openapi-ts.dev/openapi-fetch/)
over types generated by openapi-typescript · Vitest + Testing Library · ESLint (flat
config: typescript-eslint, react-hooks, react-refresh) · `nginxinc/nginx-unprivileged`
runtime image.

Deliberately not included: a router, a data-fetching cache, a CSS framework, i18n. Add
what the project needs (`npm i react-router`, `@tanstack/react-query`, `tailwindcss
@tailwindcss/vite`, `i18next`); the patterns below are what matters.

```
src/
  main.tsx           bootstrap
  App.tsx            starter screen: shows backend meta via the typed client (replace it)
  App.test.tsx       example tests (fetch stubbed with vi.stubGlobal)
  config.ts          runtime config (window.__APP_CONFIG__) + build version
  api/client.ts      THE typed API client — route every call through it
  api/schema.d.ts    GENERATED from ../api/openapi.yaml (npm run api:types); committed, never edited
  test/setup.ts      jest-dom matchers, cleanup
public/config.js     dev-time runtime config (same shape the image renders from env)
nginx/default.conf.template   the runtime image's server: /healthz, /config.js, SPA fallback
```

## Three things that make the image environment-agnostic

1. **Runtime config, not build-time env.** Values that differ per environment come
   from `/config.js`, loaded in `index.html` before the bundle and exposed through
   `src/config.ts`. In the Docker image nginx renders it from `APP_*` env vars at container
   start (`location = /config.js` in the template), so the **same image** serves dev,
   stage and prod. In development `public/config.js` plays that role. Do **not** put
   environment-specific values in `VITE_*` variables: they are inlined at build time and
   would force one image per environment.

   | `APP_*` env var (image) | `config.ts` | Meaning |
   |---|---|---|
   | `APP_API_BASE_URL` (default empty) | `config.apiBaseUrl` | prefix for API calls; empty = same origin (recommended) |
   | `APP_ENVIRONMENT` (default `prod`) | `config.environment` | label only; mirrors the backend's `ENVIRONMENT` |

   Adding a key: `config.ts` interface + defaults → `public/config.js` → the `return 200`
   line in `nginx/default.conf.template` → `ENV APP_…=""` in the Dockerfile (an undefined
   variable would render as a literal `${APP_…}`) → the `environment:` block of the
   `frontend` service in `ops/compose/*.yml`.

2. **Same origin.** The SPA calls `/api/…` relative to its own origin; the edge (nginx in
   Compose, Ingress in Kubernetes) routes those prefixes to the backend. No CORS, no API
   host to configure. In development `vite.config.ts` proxies the same prefix list to the
   backend stack, so `http://localhost:5173` behaves like production. The prefix list
   must match `backend/config/urls.py` and `ops/nginx/*.conf`.

3. **Build identity only at build time.** `VITE_APP_VERSION` (CI passes `sha-<sha>` or
   the tag) is the one build arg; it is shown in the UI next to the backend's version.

## The typed API client

```ts
import { api } from "./api/client";
const { data, error, response } = await api.GET("/api/v1/meta/");
//      ^ typed from api/openapi.yaml: data is components["schemas"]["Meta"] | undefined
```

The types come from the backend's OpenAPI schema. When the backend changes an endpoint
it runs `make api-schema` (regenerates `../api/openapi.yaml` and `src/api/schema.d.ts`)
and commits both; `npm run api:types` alone regenerates the types from the committed
schema. CI (`frontend.yml`) fails if `schema.d.ts` is stale, and a breaking backend
change fails `npm run typecheck` here instead of failing in production.

## Testing

Vitest with jsdom and Testing Library. `App.test.tsx` shows the pattern: stub `fetch`
with `vi.stubGlobal` (the client resolves `fetch` per call, so stubs are honoured), render,
assert. For larger suites consider `msw`.

## Development

| Variable (`.env.local`, see `.env.example`) | Default | |
|---|---|---|
| `VITE_PORT` | `5173` | dev server port (the nginx dev edge proxies `/` here) |
| `VITE_PROXY_TARGET` | `http://localhost:8050` | where backend-owned paths are proxied |

Two ways to open the app in dev: `http://localhost:5173/` (Vite directly, backend paths
proxied) or `http://localhost:8050/` (the stack's nginx proxies `/` to Vite including
HMR). Both are same-origin with the API. Admin login works through either. For the
second route Vite listens on all interfaces (`server.host: true`): a container cannot
reach a localhost-only bind on the host, so the dev server is also visible on your LAN.

## The image

`Dockerfile`: `node:24-alpine` builds `dist/`, `nginxinc/nginx-unprivileged:stable-alpine`
serves it as uid 101 on **port 8080** (no root, no capabilities; k8s `runAsNonRoot`-ready).
The nginx entrypoint renders `nginx/default.conf.template` with `envsubst`, restricted to
`APP_*` so nginx's own `$variables` survive.

| Path | Served by the image's nginx |
|---|---|
| `/healthz` | `200 ok` — Compose healthcheck, k8s liveness/readiness |
| `/config.js` | runtime config rendered from `APP_*` (no-store) |
| `/assets/*` | hashed bundles, `Cache-Control: public, immutable` |
| `/index.html`, `/*` | SPA shell (`no-cache`), history fallback |

The image only serves files; it never proxies to the backend (that is the edge's job),
so it has no knowledge of where the backend lives.

## Running a Next.js frontend instead

The template defaults to a static React SPA because it is the simplest runtime: one
static image, no server process, trivially cacheable. A Next.js app fits the same layout
and the same rules; what changes is that the frontend becomes a **Node process**.

| | Vite SPA (default) | Next.js |
|---|---|---|
| Runtime image | nginx-unprivileged, port 8080 | `node:24-alpine`, port 3000, `output: "standalone"` |
| Health probe | `/healthz` (nginx `return 200`) | `app/healthz/route.ts` → `new Response("ok")` |
| Runtime config | `/config.js` rendered by nginx from `APP_*` | server code reads `process.env` directly; client components get the same object from a route handler `app/config.js/route.ts` (`export const dynamic = "force-dynamic"`) or a server component that injects it |
| Dev proxy for backend paths | `server.proxy` in `vite.config.ts` | `rewrites()` in `next.config.ts`, e.g. `{ source: "/:prefix(api\|admin\|rosetta\|healthz\|readyz)/:path*", destination: \`${process.env.BACKEND_URL}/:prefix/:path*\` }` (dev only; in prod the edge routes) |
| Build identity | `VITE_APP_VERSION` | `NEXT_PUBLIC_APP_VERSION` build arg |
| CI (`frontend.yml`) | unchanged | unchanged (`npm run build`, same image/tag scheme) |
| Compose | `expose: 8080`, `wget /healthz` | `expose: 3000`, healthcheck `node -e "fetch('http://127.0.0.1:3000/healthz').then(r=>process.exit(r.ok?0:1)).catch(()=>process.exit(1))"` |
| Edge (`ops/nginx/*.conf`) | `upstream spa { server frontend:8080; }` | `server frontend:3000;` — `/` already covers `/_next/*` |
| Kubernetes | Deployment + Service :8080 | Deployment + Service :3000, same probes paths; give it CPU/memory (it renders) |

Dockerfile for the Next.js variant (replace `frontend/Dockerfile`; `next.config.ts` must set
`output: "standalone"`):

```dockerfile
# syntax=docker/dockerfile:1
FROM node:24-alpine AS build
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
ARG NEXT_PUBLIC_APP_VERSION=dev
ENV NEXT_PUBLIC_APP_VERSION=$NEXT_PUBLIC_APP_VERSION NEXT_TELEMETRY_DISABLED=1
RUN npm run build

FROM node:24-alpine AS runtime
ENV NODE_ENV=production PORT=3000 HOSTNAME=0.0.0.0 NEXT_TELEMETRY_DISABLED=1
WORKDIR /app
RUN addgroup -S app && adduser -S app -G app
COPY --from=build --chown=app:app /app/.next/standalone ./
COPY --from=build --chown=app:app /app/.next/static ./.next/static
COPY --from=build --chown=app:app /app/public ./public
USER app
EXPOSE 3000
CMD ["node", "server.js"]
```

Everything else in this repository (the API contract and generated types, same-origin
routing, per-component CI and deploys, the Kubernetes contract) applies unchanged. If
the app needs SSR/SEO, choose Next.js; for admin panels and dashboards the static SPA
is the better default.

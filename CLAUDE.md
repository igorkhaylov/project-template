# CLAUDE.md

Guidance for AI coding agents (and humans) working in this repository.

## Layout and the one rule

```
backend/   Django + DRF. Self-contained: own Dockerfile (context = backend/), own tooling (uv, ruff, pytest).
frontend/  React + Vite + TS SPA. Self-contained: own Dockerfile (context = frontend/), own tooling (npm).
ops/       Everything that composes them: compose files, nginx edge, scripts, k8s notes. No app code.
api/       openapi.yaml — the contract. Generated by the backend, consumed by the frontend. Never hand-edit.
```

**Rule:** `backend/` and `frontend/` never reference anything outside themselves (no
`../` in Dockerfiles, configs or imports). Each builds and runs on its own; `ops/` is
the only place that knows both exist. Images are environment-agnostic: configuration is
read at runtime from env vars (backend) or `/config.js` (frontend), never baked in at
build time. Build-time args carry build identity only (`APP_VERSION`, `VITE_APP_VERSION`).

## Commands (run from the repo root)

```
make init                  first run: .env + secrets, MinIO bucket, dev stack, migrate, collectstatic, npm ci
make dev up / dev run      backend dev stack / Django dev server (API + admin at :8050)
make fe-dev                Vite dev server on the host (:5173; also proxied at :8050)
make dev test / dev lint   pytest / ruff inside the dev container
make fe-test / fe-lint / fe-typecheck
make api-schema            regenerate api/openapi.yaml + frontend/src/shared/api/schema.d.ts (commit both)
make up                    local production-like stack (both images built from source)
```

## Things that must stay in sync

- **Backend-owned URL prefixes** (`api`, `admin`, `rosetta`, `__debug__`, `healthz`,
  `readyz`, with optional `en|ru` language prefix) appear in three places:
  `backend/config/urls.py`, `ops/nginx/nginx.conf` + `nginx.dev.conf`, and
  `frontend/vite.config.ts`. A new top-level backend prefix goes into all of them.
- **The API contract.** Any change to DRF views/serializers → `make api-schema` →
  commit `api/openapi.yaml` and `frontend/src/shared/api/schema.d.ts` with the change. CI fails
  on either side if they drift.
- **Health probes.** `/healthz/` (liveness, no dependencies) and `/readyz/` (DB + cache)
  are implemented once in `common.health`. `common.middleware.HealthCheckMiddleware`
  answers them first (keep it first in `MIDDLEWARE`: that is what bypasses
  `ALLOWED_HOSTS` for probes); the routed views in `common.views` put them in the
  OpenAPI schema. Change the payload in `common.health` and the serializers together.
- **Release step vs web process.** `backend/scripts/release.sh` (migrate, collectstatic,
  first superuser) runs once per deploy; `scripts/entrypoint.sh` only starts gunicorn.
  Never move migrations back into the web process.

## Conventions

- Backend: see `backend/README.md`; settings are env-driven (`ENVIRONMENT` selects
  dev/test/stage/prod), `DATABASE_URL`/`REDIS_URL` override the Compose-style variables.
- **Every change to code inherited from django-template is logged in `DEVIATIONS.md`**
  (one row per deviation, with an ID). Add a row when you modify an inherited file;
  additions of new files/routes are listed there too, in their own section.
- Frontend: layered `src/` (`app → pages → widgets → features → entities → shared`;
  imports point downwards only, cross-layer imports via `@/`; rules and naming in
  `frontend/docs/architecture.md`). Typed API calls through `src/shared/api/client.ts`
  only; runtime config through `src/shared/config/appConfig.ts`, never `import.meta.env`
  for environment-specific values. Prettier formats; `npm run check` is what CI runs.
- CI is per component with path filters (`.github/workflows/backend.yml`,
  `frontend.yml`); `deploy.yml` deploys the component that changed.
- Kubernetes readiness contract: `ops/k8s/README.md`.
